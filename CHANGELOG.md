Versions are set in `pyproject.toml`; there are no release tags or PyPI releases yet.

## 0.20.0 -- unreleased
- A date code without a language prefix is drawn in the interface language's own names (round 7, follow-up 4b): measured, PowerPoint and Excel for Mac, 17 October 2026, switching Office's interface language (region Dutch (Belgium)): an unprefixed code named 5 January, 17 March, 20 May and 31 December 2026 in the interface language, each region alike (fr-FR = fr-BE, es-ES = es-MX), and in French and Spanish not with the prefixed names. New `INTERFACE_NAMES` and `date_names(code, locale)`; `names_language` gives `fr` or `es` for such a code. French: `mmm` `janv mars mai déc` (`[$-40C]`/`[$-80C]`: `janv.`, `déc.`), `ddd` as `[$-40C]` (`lun. mar. mer. jeu.` in a PowerPoint chart; an Excel cell showed `lun mar mer jeu`, and a chart is what is drawn); the other months are fr-FR's with the trailing dot removed and the other days fr-FR's -- a rule inferred from the 16 names measured, consistent with all of them, not measured for the rest. Spanish: `ene mar may dic`, `lun mar mié jue` -- not es-ES's (`ene.`, `lu.`) but the measured `[$-A]` set, which every measured name agrees with (es-MX's without dots would too, differing only in September, `sep`/`set`, not measured). Any fr-* or es-* locale takes these; English, German and Dutch interfaces showed their prefixed names (unchanged); Italian was not measured and keeps it-IT's. A prefix is unchanged under every interface language (measured).

## 0.19.0 -- unreleased
- A region's date names are its language's (round 7, L5): a date category under `[$-80C]` (French (Belgium), as Excel stores `[$-fr-BE]`) was drawn with en-US's names, its id not listed; and a locale such as fr-BE or en-BE fell back to en-US's names for an unprefixed code. Measured in Excel for Mac, 17 October 2026: en-BE and en-IE named a date as en-US, fr-BE and fr-CH as fr-FR, de-BE and de-CH as de-DE, and Excel stored `[$-fr-BE]` as `[$-80C]`, `[$-en-IE]` as `[$-1809]`, `[$-fr-CH]` as `[$-100C]`, `[$-en]` `[$-9]`, `[$-fr]` `[$-C]`, `[$-de]` `[$-7]` (and `[$-nl]` `[$-13]`, 16 October), each with its language's names; a raw `[$-en-BE]` showed English. So `LCIDS` lists those ids too, new `LANGUAGES` (en, nl, de, fr, it, each with the tag whose names it takes) and `names_tag(tag)` give a region its language's names, a `[$-ll-CC]` prefix is read whenever its language has names (`[$-de-BE]`, `[$-it-CH]`), and a locale's region takes its language's names where no prefix says otherwise. `[$-de]` reads as the tag, not the id 0xDE. ooxml-edit 0.44.0 writes these codes; a test checks the two tables agree where both are installed. Ids not measured (`[$-411]`, `[$-C09]`) are read as before, in the locale's language.
- Spanish regions keep their own names (measured on PowerPoint and Word for Mac's charts, 17 October 2026): `[$-80A]` (es-MX, as Office re-saves `[$-es-MX]`) abbreviates days `lun. mar. mié.`, `[$-A]` (es) months `ene ... set` and days `lun mar mié`, `[$-C0A]` (es-ES) `lu. ma. mi.`; full names alike. `NAMES` lists es-MX and es; `LANGUAGES` has no es, so another Spanish tag (`[$-es-AR]`) is not read and the locale's names apply. `[$-810]` (it-CH) and `[$-10]` (it) draw it-IT's names.
- A chart Office re-saved draws its dates again (measured, the same day): a code with a language tag (`[$-en-BE]d\ mmm`) is re-saved as an `mc:AlternateContent` in the cache -- a `c16r2` Choice's `formatcode2` holding the tag, a Fallback `c:formatCode` of `[$]...` -- and the axis' `c:numFmt` gains a `c16r2:formatcode2` attribute; the cache read as having no code and the categories were drawn as serials (`46027`). Now the Choice's `formatcode2` is read, else the Fallback's code (a bare `[$]` is the locale's language), and a `numFmt`'s `formatcode2` before its `formatCode` (axes, data labels): English for `[$-en-BE]`, German for `[$-de-BE]`, as Office drew them.

## 0.18.0 -- unreleased
- PowerPoint draws a rich chart title in its own fonts, not the text cascade's (new `ChartRules.rich_title_fonts`, `True` for `POWERPOINT`, `False` for `WORD`). Measured, PowerPoint 16 for Mac's PDF export, 16 October 2026, in a deck whose text boxes are Aptos (`+mn-lt`): a `c:title/c:tx/c:rich` whose paragraphs state no `a:defRPr` and whose runs name no face (new `title_states_no_font(chart)`) is **ArialMT, regular**, black, at the run's size or 18 pt -- at chart-wide sizes none, 8 and 24 pt, under an unsized title `c:txPr`, under a chart-wide `c:txPr` naming `+mn-lt` (still Arial), and at 24 pt with the run's `sz="2400"`; the caller's cascade had drawn it Aptos. A title whose paragraph states an `a:defRPr` (new `title_states_defaults(chart)`) is the theme's **minor face** unless a face is stated, and **bold** unless `b` is stated: `sz="1862"` alone, Aptos bold; `b="0"` with or without `+mn-lt`, regular; `+mn-lt` and `sz` on the paragraph and the run without `b`, bold. A run naming a face without paragraph defaults keeps it, regular. Colour, and size where stated, stay the caller's; the title band is measured in the face drawn. Not covered (not measured): a title `c:txPr` stating a face or a size, a list style naming a face, an empty `<a:defRPr/>` (read as none), East Asian faces, axis titles, Word. `RICH_TITLE_FALLBACK_FACE` is `"Arial"`. Measured and not applied: chart glyphs drawn at whole points (docs/word-and-powerpoint.md).

## 0.17.0 -- unreleased
- Date categories are printed as dates: a category kept as a serial under a date code (`[$-413]d\ mmmm\ yyyy`, as ooxml-edit's `date_format` writes them) was drawn as its number (`46027`); now new `ooxml_common.dates.format_serial(value, code, locale, date1904=...)` prints it -- day, month and year tokens, the code's literal text as written. Measured on PowerPoint and Word 16 for Mac, 16 October 2026: 46027, 46063 and 46096 under `[$-413]d\ mmmm\ yyyy` read `5 januari 2026`, `10 februari 2026`, `15 maart 2026`; under `[$-407]d\ mmm\ yyyy` `5 Jan 2026` ... `15 Mär 2026`; under `[$-409]dd/mm/yyyy` `05/01/2026` ... `15/03/2026`. The month and day names (`NAMES`, `LCIDS`: en-US, en-GB, nl-NL, nl-BE, de-DE, fr-FR, es-ES, it-IT) were measured in Excel for Mac the same day, and are ooxml-edit 0.38's table (a test checks the two agree where both are installed). The `[$-LCID]` prefix names the language; a code without one (or with one not listed) takes the locale's `language` -- measured, an unprefixed code and a date axis took the interface language's names -- and a language with no measured names en-US's. A `/` is printed as `/`: Office shows the viewer's region separator there (`-` in a Dutch (Netherlands) region, `.` in a German one, `/` in English (UK and US), French, Spanish, Italian and Dutch (Belgium) ones), which `Locale` does not hold. A time code (`h:mm`), a token not read (`ddddd`) or a serial that names no day keeps the number, as before. New `SourceChart.date1904` (`c:date1904`) counts serials from 1904.
- PowerPoint draws a chart's automatic title: a `c:title` with no `c:tx` over one series was not drawn (`ChartRules.auto_title=False`); it is now the series' name, bold, in the theme's minor face, at 1.2 times the chart's `c:txPr` size rounded to the point, 18 pt where the chart states none (`powerpoint_auto_title`, `powerpoint_auto_title_size`). Measured, PowerPoint 16 for Mac's PDF export, 16 October 2026: chart-wide 8, 10, 11 and 24 pt gave 10, 12, 13 and 29 pt, none 18 pt; a title `c:txPr` without a size changed nothing. What the title's own `c:txPr` states (new `SourceChart.title_text_properties`) is drawn over those defaults, as the schema says (not measured with a size). Over several series PowerPoint shows its own words, which are not measured, and nothing is drawn, as before. Word's automatic title is unchanged (the caller's, docx2svg's).

## 0.16.0 -- unreleased
- Numeric chart categories are printed in their format and the locale: a category axis (and a category name in a data label or a per-point legend) whose `c:cat` is a number cache prints each number through the cache's `c:formatCode` -- or the point's own `formatCode`, which the schema puts first -- with `format_number(value, code, locale)`. Measured on PowerPoint 16.106 for Mac, 13 October 2026: 1.5, 2.25 and 1234.5 under `General` read `1.5 2.25 1234.5` in an English (United States) region and `1,5 2,25 1234,5` in a Dutch (Belgium) one; under `#,##0.00` `1.50 2.25 1,234.50` and `1,50 2,25 1.234,50`. Previously they were invariant text whatever the code (`1234.5`, never `1,234.50`). A date or time code keeps that invariant text (the serial), as before: dates are not formatted here. Read as the new `SourceChartSeries.category_values` and `category_point_format_codes`; `categories` and `ChartData` keep the invariant text. A scatter's `c:xVal` is unchanged (not measured).

## 0.15.0 -- unreleased
- One locale for every library: new `ooxml_common.locales.Locale`, the regional settings Office takes from its machine rather than from the file -- `decimal_separator`, `thousands_separator`, `date_order` (`dmy`, `mdy` or `ymd`), `language` (a BCP 47 tag, kept in its conventional case: `nl_be` is `nl-BE`) and `list_separator`. Frozen, hashable, picklable and validated (one character each, not a letter or digit; the thousands and list separators not the decimal one). The default is `EN_US`, fixed -- never the machine's locale, so a file draws the same on any server; the caller passes the user's. `locale_for(tag)` finds a listed locale by tag and raises `LookupError` for any other rather than guessing; `KNOWN_LOCALES` lists only `en-US`, since what Office does in another locale is measured before it is listed.
- A chart prints its numbers in a locale: `format_number(value, code, locale)` and `ChartBuilder(..., locale=...)` write tick labels and data labels (values, percentages, bubble sizes, a label's `VALUE` field) with the locale's separators, the format's own text unchanged: in a Dutch locale `"€"#,##0.0"m"` is `€12,4m`, as PowerPoint and Word 16 for Mac drew it on a Dutch machine. `ChartData` stays in the invariant `.` and `,`. Without a locale the output is what it was.

## 0.14.0 -- unreleased
- A table can carry its style's background: `TableData.background` is a fill drawn once over the whole table, under every cell (a gradient runs across the table, not across each cell; a cell without a fill of its own, or with a translucent one, shows it), and `TableData.effects` apply to the table as a whole, as a shape's do -- the `a:tblBg` of PowerPoint's "Themed Style 1" and "2", a theme fill style with an effect style's shadow. ## 0.13.0 -- unreleased
- A paragraph holding only whitespace draws its bullet, as PowerPoint does: a space, a tab, a no-break space or several, in one run or more, first paragraph or later, in a placeholder or a text box, wrapped or not. The bullet (or number, or picture) takes the whitespace run's size and colour and the line is as tall as that run; a break before the text leaves the bullet alone on the first line. An auto-number numbers and counts such a paragraph, and no longer counts an empty one (no run, or only an empty run), which draws nothing: `a`, whitespace, `b`, empty, `c` is 1, 2, 3, -, 4, not 1, -, 3, -, 5. Measured on PowerPoint 16's PDF export (`tests/test_blank_paragraphs.py`). New `DrawingRules.blank_paragraphs`: `"text"` for PowerPoint; Word keeps `"empty"`, what was drawn before, as it is not measured.

## 0.12.0 -- unreleased
- An SVG picture whose root's size is in `pt`, `pc`, `in`, `cm`, `mm`, `em`, `ex` or `%`, or is not stated, can be rasterised as PowerPoint draws it: new `ooxml_common.svgimage`, whose `natural_size` is the size PowerPoint draws an SVG at before stretching it to its frame -- a length at 96 px to the inch, an `em` of the root's font-size or 12 px, the `viewBox`'s size for a percentage or no size, and 500 px (a percentage of it) without a `viewBox` -- and whose `with_pixel_size`/`with_pixel_sized_images` restate an SVG's (or every `data:image/svg+xml` picture in a page's) root `width` and `height` in pixels, add a `viewBox` of that size where there is none, and re-encode a non-UTF-8 SVG as UTF-8, changing nothing else. resvg-py 0.5 drew nothing for `width="72pt"` ("SVG has an invalid size") or a Latin-1 SVG, and CairoSVG drew an SVG with no `viewBox` unscaled. Measured on PowerPoint 16's PDF export of 30 SVG pictures (pptx2svg's `tools/make_svg_size_probe.py`), every one where `natural_size` puts it. The SVG is read as untrusted: expat, nothing loaded, only to the root's start tag; one with an internal DTD subset (entities) is left alone.

## 0.11.0 -- unreleased
- An axis in reverse order is drawn reversed: `c:scaling/c:orientation val="maxMin"` lists a category axis' first category at the top of a bar chart and at the right of a column chart, puts a value axis' minimum at the top (or the right), and turns a scatter's or a bubble chart's x and y axes round. The axis crossing it stands where its own `c:crosses` says, `max` being the reversed axis' far end -- the plot's near edge -- and an unstacked bar grows from where the category axis crosses (a column chart whose reversed value axis is crossed at its maximum rises from the bottom edge). A clustered bar chart's group and its legend turn round with the category axis; data labels on a reversed value axis stand beyond the bar's hanging end. Measured on PowerPoint 16's export of charts ooxml-edit writes with `set_axis_scale(reverse=True)`; a 3-D scene is not reversed.
- Minor gridlines (`c:minorGridlines`) are drawn, under the major ones, at the minor unit and never at a major value or the crossing; a category axis' major gridlines at every band edge, both plot edges included; a scatter draws its y axis' gridlines before its x axis'. Measured on PowerPoint 16.
- PowerPoint charts draw their axis titles, where Word does (`ChartRules.axis_titles` is now true by default): measured on PowerPoint 16 on columns, bars, lines, scatter and bubble charts with 10 to 20 pt titles, every title within PowerPoint's half-point raster of Word's placement. A scatter's and a bubble chart's titles are drawn too, in either application, the x axis' at the bottom and the y axis' at the left.
- A clustered horizontal bar chart puts its first series at the bottom of each group and lists its legend from the last series, in PowerPoint as in Word (`bars_upward` and `legend_order="stack"` are now the defaults): measured on PowerPoint 16 with two and three series, the legend at the right and below; stacked columns beside a side legend reverse too, stacked bars and clustered columns do not. A bar's data label now stands on the bar `bars_upward` drew.
- Not changed: Office's automatic value axis that does not start at zero for bars (PowerPoint drew 105..145 for values of 120 to 141; we draw 0..160).

## 0.10.0 -- 2026-10-11
- Font folders are walked once per process, not on every text measurement: `with_subfolders` (and so `user_search_dirs`, `user_families`, `search_dirs`), `system_font_dirs` elsewhere than macOS and `cloud_font_dirs` keep their answer and check it with one stat per folder -- none per file, no listing -- walking again only where a folder's modification time changed. A text-fit report with a 600-file, 30-folder font folder went from 633 stats and 62 listings to 32 stats; a pptx2svg render with host fonts from 1,264 stats and 124 listings to 62. A changed folder also drops the face index, font bytes and advance tables, so a font added at any depth is seen by the next lookup (previously never, within a process). New `refresh_font_dirs()` forgets every walk and index, for what a folder's time does not show (a file rewritten in place, coarse file-system times). The walk lists what `rglob("*")` with `is_dir()` listed, in the same order (`docs/fonts.md`).

## 0.9.0 -- 2026-10-10
- A data label with text of its own is drawn: a `c:dLbl`'s `c:tx` -- rich text with each run's size, face, colour, bold, italic and underline, or a cell's cached string -- is printed instead of the composed label, even with every `c:show*` flag off, on every chart kind; its `CELLRANGE`, `VALUE`, `SERIESNAME`, `CATEGORYNAME`, `PERCENTAGE` and `BUBBLESIZE` fields are the point's. "Value From Cells" (`c15:datalabelsRange` with `c15:showDataLabelsRange`) prints the range text first, `alpha; North; 3`. Read as `SourceChartDataLabels.text`/`show_range` and `SourceChartSeries.label_range`; measured on PowerPoint 16's export of pptx2svg's `tools/make_point_label_probe.py`. Word's charts get the same.
- Text in a symbol face can be drawn without the face: `ooxml_common.text.symbol_fonts` says which Unicode character every code of Symbol, Wingdings, Wingdings 2, Wingdings 3 and Webdings stands for (0x20..0xFF and its private-use alias U+F020..U+F0FF; `to_unicode`, `translate`), generated by `tools/derive_symbol_maps.py` from the Unicode Consortium's published tables (Adobe's Symbol table; UTC L2/11-344 for the Wingdings sets, by character name) under a few drawing preferences compared with PowerPoint 16's export (`PREFERRED`: Wingdings' `ü` is U+2713, the light check PowerPoint draws). `RenderContext.mapped_symbol_faces` draws a run or a character bullet in such a face as those characters, in `FALLBACK_FAMILIES`, while it is still measured as the face.
- The integers Word lays Symbol and Wingdings out with moved here from docx2svg (`text.recorded_symbol_faces`, unchanged), and `symbol_fonts.recorded_font_metrics` turns them into a measurer's table, so both renderers lay an absent Symbol or Wingdings out at its own advances.
- The font report says what happens to an absent symbol face instead of "widths guessed".
- A text field's type is read: `SourceTextRun.field_type` is `a:fld@type` (`"slidenum"`, `"datetime1"`, a chart label's `"CELLRANGE"`), so a renderer can evaluate the field for the slide it draws instead of drawing its cached text. `None` for a plain run.
- Python 3.14 and 3.15: CI runs the suite on both, on Linux, macOS and Windows, and the
  classifiers declare them. `requires-python` stays `>=3.10`. No code change was needed.
