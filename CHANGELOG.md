# Changelog

Versions are set in `pyproject.toml`; none is on PyPI yet. Each version that reaches `main`
is tagged `v<version>` on the commit that brought it, from 0.28.0; the earlier ones were
never tagged.

## 0.29.0 -- unreleased
- One reading of a number format code (review, S1): new `ooxml_common.numfmt`. `sections(code)` cuts a code where Excel does (not at a quoted, escaped, `_` or `*` `;`), `tokens(section)` lexes a section into `Token`s (dates, times -- `m` read as minutes after an hour or before a second --, elapsed time, AM/PM, digits, exponent, percent, `General`, `@`, quoted and escaped text, padding, fill, colour, condition, locale, other brackets), `classify(code, section=None)` says what a section shows (`Classification`: `kind` one of `KINDS` -- general, number, percent, date, time, datetime, text --, `elapsed`, `lcid`) and `is_date_code(code, section=None)` whether it is a date or a time. The first section decides unless another is asked for: measured in Excel for Mac 16.106 (2026-10-25), `0;[Red]d` showed a positive serial as `46028` and `CELL("format")` said a number, while its negative serial showed `####`. Dates and times are also `e`, `g`, `b`, the Thai `ว ด ป` and `ช น ท`, `[ช]`, `上午/下午` and `A/P` alone, and a first section with `[$-F800]`/`[$-x-sysdate]` (the system's long date) or `[$-F400]`/`[$-x-systime]` (its time), each measured. `numfmt.MEASURED` is the table: 108 codes with the kind and the text Excel showed, which `tests/test_numfmt.py` holds `classify` to (and lists where ooxml-edit's own copy still differs, with it installed); xlsx-agent runs it through its reading. Standard library only.
- `dates.is_date_code` is now `numfmt.is_date_code` (the same function), and `dates` and `chart.layout` read codes with `numfmt`: their own date checks and section splitters are gone. What changes: `dates.is_date_code("0;[Red]d")` (and `0;0;d`, `0.00E+00;d`) is `False`, the codes above are `True`; a chart's number category is printed as a date or kept as the cache's text only when the section its value is shown with is a date or time -- `0;[Red]d` prints a positive serial as a number (`46028`, as Excel showed), and `[h]`, `[ss]`, Thai, era and system codes keep the cache's text instead of being printed as a number or as their own letters (`ว/ด/ปปปป`). `format_number` and `format_serial` no longer cut a section at `\;`, `_;` or `*;` (Excel showed `0\;0` as one section). `format_serial` no longer prints a code with Thai elapsed hours (`[ช]`), a time. Every other output is unchanged (60,000 generated codes compared against the old functions).

## 0.25.0 -- unreleased
- An effect's filter region fits what it can reach (round 10, survey 6): `drawingml.effect.render_effects(..., bounds=...)` takes the extent of what the filtered element draws, and the region is that grown by each effect's reach -- three standard deviations of its blur (four for an inner shadow, which blurs the inverse of the shape) plus a shadow's offset (on every side: the blur is drawn before it is moved, and resvg moves it along the page's axes) and two user units, a soft edge's blur too (resvg's blur reads the region past the edge) -- in user space (`effect_region`), instead of 200% of the bounding box, which a rasteriser blurs whole: a full-slide shape's shadow blurred four slides of pixels. `render_shape` gives the bounds for a shape with no text in a preset that stays in its box (rectangles, rounded and snipped ones, ellipses; the outline twice its width), `render_image` for a picture (its frame, a stretch pushed out of it, its outline); a shape drawn turned (its rotation, or an enclosing group's: new `RenderContext.turned`) keeps the old region, since the rasteriser's antialiasing of a turned edge can come out a sample different at another region origin. Same PNGs on the corpus; the SVG's `<filter>` attributes change. Where the old region was shorter than a blur's reach -- a small shape with a large blur, its shadow cut square at half the shape's size from it -- the blur is no longer clipped (a fidelity fix: 322 of 1,040 made-up shapes and pictures with every effect at sizes from 12 px to the slide, all such cases; the other 718 byte-identical).
- `text.fontmap.mapped_font` looks a normalised name up in an index of the mapping (cached by the mapping's items, so a mapping changed in place is indexed afresh) instead of normalising every key per call -- about 50,000 normalisations on a template (round 10, survey 9).
- One parse per SVG for the rasteriser's checks (round 10, survey 7): `fonts.rasterdb.parsed_svg(svg)` keeps the last two parses, which `needed_font_files` and pptx2svg's glyph check share. `metafile.inline_metafile_images` reads a picture's root from the first 768 bytes of its payload before decoding it whole, and keeps what it inlines per payload (64 pictures, 32 MB of payload).
- A one-time warning for a slow file system (round 10): `fonts.slowfs`. The first time a font folder in use (`font_dirs`, `OOXML_FONT_DIRS`; checked by `office.user_font_dirs`), the font bundle or the library itself is on WSL's mount of a Windows drive (9p, drvfs) or a network file system (NFS, SMB/CIFS, FUSE network mounts), a warning on the `ooxml_common.fonts` logger names the folder and file system and says to keep the fonts on the local disk (bake them into the image, or copy them to a local folder at start) and point `OOXML_FONT_DIRS` there. Linux only, from `/proc/self/mountinfo`; once per process per folder; standard library only.

## 0.24.0 -- unreleased
